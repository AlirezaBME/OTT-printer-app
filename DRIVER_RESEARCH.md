# Canon LBP6030 / LBP6040 / LBP6018L — Driver Research & Protocol Analysis

## 1. Executive Summary

The **Canon LBP6030, LBP6030B, LBP6040, and LBP6018L** laser printers are host-based ("winprinter" / GDI-style) desktop laser printers. Unlike enterprise office copiers or PostScript laser printers, they do not contain embedded PostScript or PDF interpreters. They require the host computer (or in our case, the Android device) to completely rasterize the document into a 1-bit monochrome bitmap and compress it using proprietary Canon framing.

---

## 2. Official Canon Linux Driver Architecture

Canon provides official Linux driver packages supporting this family:
- **`cnrdrvcups-lb`** (Canon UFR II/UFRII LT Printer Driver for Linux)
- **`cnrdrvcups-sfp`** (Single Function Printer package)

### Components of Canon's Linux Driver:
1. **PPD (PostScript Printer Description) Files:** Open-source / redistributable PPD files defining page sizes, resolutions (600 DPI, 300 DPI), and printer capabilities.
2. **CUPS Filter (`rastertoufrii` or `rastertocnr`):**
   - The filter receives standard CUPS raster data from `cups-filters` (generated by Ghostscript or `pdftoraster`).
   - The outer wrapper is open-source (GPL licensed).
   - **Proprietary Core Library:** The actual conversion of raster bytes into Canon's binary stream is performed by proprietary shared libraries (`libcanon_ufrii*.so`, `libufr2filter*.so`).
3. **Proprietary Licensing Restrictions:** Canon's official binary libraries are distributed under proprietary Canon EULAs that restrict reverse engineering, extraction, and redistribution outside their packaged Linux installer. They are not compiled for Android's Bionic libc and cannot be bundled into an Android APK.

## 3. Page Description Languages: CARPS2 vs UFRII LT

When queried over USB via the standard IEEE-1284 Device ID string (`bRequest=0, bmRequestType=0xA1`), the Canon LBP6030 family reports:
```
MFG:Canon;CMD:CARPS2,UFRII LT;MDL:LBP6030/6030B/6018L;CLS:PRINTER;DES:Canon LBP6030/6030B/6018L;
```

Notice that the printer hardware firmware advertises **both `CARPS2` and `UFRII LT`** in its command set (`CMD`).

### What is CARPS2?
- **CARPS** (Canon Advanced Raster Printing System) is Canon's proprietary raster page description language used across personal laser printers and multi-function machines (such as MF3110, MF5730, and the LBP6000 series).
- **Compression:** CARPS2 compresses 1-bit monochrome raster rows using standard **CCITT Group 4 (ITU-T T.6) 2D fax compression** or run-length PackBits encoding.
- **Packet Structure:**
  - Initial synchronization: `\x1b[K` or `\x1b@`
  - Page configuration: `\x1b[<resolution>;<paperCode>;<copies>z`
  - Page dimensions: `\x1b[<page>;<width>;<height>p`
  - Data packets: `\x1b[<length>r` followed by compressed binary data.
  - Page termination: Form Feed `0x0C` (`\f`).

### What is UFRII LT?
- **UFRII LT** (Ultra Fast Rendering II - Lite) offloads graphic object rendering to the host CPU, transferring pre-rendered compressed raster data to the printer.
- **Framing:** Enclosed within standard HP PJL (Printer Job Language) header and trailer:
  ```
  \x1b%-12345X@PJL
  @PJL SET JOBNAME = "..."
  @PJL SET RESOLUTION = 600
  @PJL ENTER LANGUAGE = UFRII
  ... binary page packets ...
  @PJL EOJ
  \x1b%-12345X
  ```

## 4. Open-Source Reference Projects Investigated

1. **`ondrej-zary/carps-cups` (GPL-3.0):**
   - Implemented a clean, reverse-engineered CUPS raster filter (`rastertocarps.c`) and decoder (`carps-decode.c`) for Canon CARPS printers.
   - Proved that the raster payload inside CARPS streams consists of standard CCITT Group 4 (T.6) 2D compressed data.
   - Identified USB quirks: Canon CARPS printers require avoiding multiple interface re-attaches (`no-reattach`).

2. **`mounaiban/captdriver` & `studycapt` (GPL-2.0):**
   - Investigated Canon's older CAPT protocol (used on LBP2900/LBP3000).
   - Created Wireshark dissectors (`capt.lua`) and stream analyzers (`captstream.py`).
   - Confirmed that modern LBP6030 series departed from legacy CAPT towards CARPS2 and UFRII LT.

## 5. Clean-Room Implementation in LBP OTG Print

To guarantee 100% legal compliance and zero proprietary binary dependencies, **LBP OTG Print** implements a clean-room driver pipeline:
1. **Pure Kotlin CCITT Group 4 Encoder (`CcittG4Encoder.kt`):** An independent implementation of the international ITU-T T.6 recommendation.
2. **Modular Driver Encoders:**
   - `Carps2Encoder`: Emits native CARPS2 packets with CCITT G4 raster chunks.
   - `UfriiLtEncoder`: Emits PJL + UFRII LT chunk headers.
   - `RawPclEncoder`: Standard fallback for universal laser engines.
   - `FILE_STREAM_DUMP`: Allows writing the exact byte stream directly to a `.bin` file in internal/external storage.

## 6. Next Experimental Steps for Physical Testing

1. **Step 1 — Verify USB Descriptors:**
   - Connect printer, open USB Diagnostics screen.
   - Verify VID (`0x04A9`), PID (`0x2795`), Bulk OUT endpoint address (`0x01` or `0x02`), and IEEE-1284 string.
2. **Step 2 — Safe USB Probe:**
   - Tap "Run Safe USB Probe".
   - Confirm port status reports `Paper: Ready (0x18)` and IEEE-1284 returns `MDL:LBP6030...`.
3. **Step 3 — Test Page with File Dump Mode:**
   - Select Driver Engine: `File Stream Dump`.
   - Tap "Print". Verify the generated `.bin` stream size (~50–150 KB).
4. **Step 4 — Physical Print Test:**
   - Select Driver Engine: `Canon CARPS2`.
   - Tap "Print". Observe printer LED activity and paper feed.
   - If printer accepts job and ejects page, Milestone 4 is achieved.
   - If printer blinks error, export the Diagnostic Report JSON and inspect the captured stream.
